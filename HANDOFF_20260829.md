Written at the end of a long session. The map is finished as far as anything
reachable from a phone can finish it, and is now waiting on one thing: a
machine with Deadlock installed.

## Where it stands

    4746 boxes, 391 entities, 15 paths, 236 path nodes

All green: `batch`, `preflight`, `emit dust2`, `minimap`. The plan converts
through Valve's own `dmxconvert`, round-trips back to text, and passes its
element census.

SCRIPT ORDER, and it matters:

    preclean.py batch13.py batch17.py batch18.py batch14.py batch15.py batch16.py

the script that would clean one up - runs last. batch17 and batch18 run
before batch14 because batch14 is the zero-extent check and should see what
they just made.

## The first three things to do on a desktop

1.  COMPILE IT. Expect errors rather than success; the log is the payload.
    The two dev materials and one model are the only content it references.
2.  STAND ON A JUMP PAD. Arc or blink? trigger_catapult was my pick because
    it takes a start and a finish, which is also what a teleporter needs. If
    it blinks, the teleporters were solved from the start and two rooms
    change meaning.
3.  READ THE SPELLING PROBE. batch16 emits seven candidate classnames at the
    teleporter and sinner positions, named probe_<site>__<classname>. A
    compiler with citadel.fgd present will reject the wrong ones by name.
    TURN SPELLING_PROBE OFF before anyone plays: it stacks overlapping
    entities at each site.

Also worth doing while there: grep citadel.fgd. It answers the teleporter,
the titan question and every subclass spelling in one pass, and it is the
single highest-value file nobody has read.

## The lesson worth carrying forward

Four separate box-count failures this session all had the same shape: a
script removes existing geometry, its behaviour changes, and something
previously removed stops being regenerated. The fixes are in place - a
stash, a reconstruct, a dedupe, an orphan list - but if a wall ever leaves
ROOMS or ANGLED_DOORS again, it needs adding to ORPHANED_WALLS in the same
drop.

The other one: check output against the state the REPO is in, not against a
pristine plan. Two of those four bugs were invisible locally because the
uploaded plan carries none of the scars the committed one does.
