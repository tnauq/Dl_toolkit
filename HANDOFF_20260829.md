# Handoff, 2026-08-29

Written at the end of a long session. The map is finished as far as anything
reachable from a phone can finish it, and is now waiting on one thing: a
machine with Deadlock installed.

## Where it stands

    4746 boxes, 359 entities, 15 paths, 236 path nodes

All green: `batch`, `preflight`, `emit dust2`, `minimap`. The plan converts
through Valve's own `dmxconvert`, round-trips back to text, and passes its
element census.

SCRIPT ORDER, and it matters:

    preclean.py batch13.py batch17.py batch18.py batch14.py batch15.py batch16.py

preclean runs first because batch13 dies on a duplicate name and batch16 -
the script that would clean one up - runs last. batch17 and batch18 run
before batch14 because batch14 is the zero-extent check and should see what
they just made.

## THE SINGLE MOST USEFUL PAGE, found late and worth knowing first

    deadlockmodding.pages.dev/entity-list

Every class derived from CBaseEntity, dumped with CS2ServerGUI. It answered
the teleporter in one look after weeks of searching, and it independently
confirms every classname this project emits. GO THERE FIRST next time a
classname is in doubt - ahead of searching, ahead of the fixture, ahead of
asking anyone.

It lists classnames only, NOT keyvalues. That distinction is now the shape
of most of what is left unknown.

npc_boss_tier3 is the PATRON, with two phases and a transform sound. batch13
had been placing six of them as lane objectives; the lane guardian is
npc_boss_tier1 and batch13 now emits that. batch15's shop wiring still fires
on OnBossKilled, which is now an ANALOGY rather than a reading - nothing in
dl_example wires an output on a tier1. If lane shops never close after a
guardian dies, that is the first thing to check.

THE MIDBOSS IS A CAMP, not an npc: info_neutral_trooper_camp with
subclass_name neutral_camp_midboss, type 5, both timings -1.

CAMP TIERS, per entity: weak 120/120, medium 120/300, strong 120/360, vaults
120/120 with an EMPTY trooper type. There is no neutral_camp_normal - that
was a guess and it was wrong.

THE SINNER IS THE VAULT CAMP, on your read, and the vdata's model path
(sinners_sacrifice_vault) supports it from a direction nobody was looking.

CI CANNOT COMPILE THIS, and the reason is narrow: the CSDK ships no shaders.
See PROBE.md for the full account - the short version is that everything
else in the compile pipeline works, including Valve's compiler accepting the
emitted map, and the only missing input is licensed game content.

THE TELEPORTER, from the entity list:

    CCitadelTeleportTrigger     citadel_trigger_teleport
    CCitadelTeleportLocation    info_teleport_location

A TELEPORTER IS TWO ENTITIES - the trigger you walk into and a location you
arrive at. That second entity is why every search for a single classname
failed. Both rooms now emit both, each sending to the other, mirrored.
EMIT_UNKNOWN is on and SPELLING_PROBE is off.

CI CANNOT COMPILE THIS, and the reason is narrow: the CSDK ships no shaders.
Seven runs established that resourcecompiler runs fine on a runner without a
GPU, never hangs, and accepts our map - it dies on "No valid vcs file found
for shader complex.vfx", and .vcs files ship with the GAME. See PROBE.md.

## What is still unknown
  - WHETHER `target` IS THE RIGHT KEYVALUE on the teleport trigger. The
    entity list gives classnames and no keyvalues at all. `target` is the
    Source convention and preflight confirms it resolves to a real
    info_teleport_location, but nothing has been READ. If walking into a
    teleporter does nothing in game, start here.
  - WHETHER TITAN MEANS SHRINE OR WALKER. The proxy's sub_objectives are
    currently wired to the SHRINES, on a wiki reading plus a third-party NPC
    reference. Neither is a game file. One line in batch16 to swap back.
  - THE LID. The mechanism is read - destroyable_building fires
    OnDestroyed -> Kill on a named brush, and a neutral camp fires
    OnTrooperKilled - but the plan format cannot express a connection at
    all. That is converter work, not entity work. midboss_lid is solid
    geometry meanwhile, behind a LID switch in batch18, and the deck below
    it is already cut so the shaft is ready.
  - THE SKY CAP'S MATERIAL is a guess and will render as a grey ceiling
    rather than sky.
  - THE PATRON'S MODEL is the shrines' generator as a placeholder.

## The first three things to do on a desktop

1.  COMPILE IT. Expect errors rather than success; the log is the payload.
    The two dev materials and one model are the only content it references.
2.  STAND ON A JUMP PAD. Arc or blink? trigger_catapult was my pick because
    it takes a start and a finish, which is also what a teleporter needs. If
    it blinks, the teleporters were solved from the start and two rooms
    change meaning.
3.  WALK INTO A TELEPORTER. Both rooms are wired trigger-to-location now,
    each sending to the other. If nothing happens, the `target` keyvalue is
    the guess to fix.

    The spelling probe that used to be here is OFF - the entity list
    answered it - but SPELLING_PROBE in batch16 still works and is the tool
    to reach for the next time a classname is in doubt AND a compiler with
    the fgd is available.

Also worth doing while there: grep citadel.fgd. The entity list has since
answered the teleporter, but the FGD is still the only thing that gives
KEYVALUES - which is what most of the open questions now need. Instructions
for a non-technical helper to send that one file are in
docs/one_file_please.md.

## Where the answers actually came from

Worth recording, because the pattern held all session and none of it was the
obvious route:

    the teleporter        a community entity dump  (deadlockmodding)
    the objective chain   npc_units.vdata          (SteamDB GameTracking)
    the camp tiers        dl_example.vmap          (the gym fixture)
    the sinner            a model PATH inside the vdata
    why CI cannot compile a file-extension census of the SDK

NOT ONE of them came from a search engine answering the question directly,
and two came from an LLM answer that was CONFIDENTLY WRONG in a way that
took a compile probe and a schema dump to disprove -
`trigger_citadel_teleport` and `citadel_sinners_sacrifice` appear in no game
file anywhere.

The rule that kept working: find the file that has to contain the answer,
then read it. The rule that kept failing: ask for the answer.

## The lesson worth carrying forward

Four separate box-count failures this session all had the same shape: a
script removes existing geometry, its behaviour changes, and something
previously removed stops being regenerated. The fixes are in place - a
stash, a reconstruct, a dedupe, an orphan list - but if a wall ever leaves
ROOMS or ANGLED_DOORS again, it needs adding to ORPHANED_WALLS in the same
drop.

The other one: check output against the state the REPO is in, not against a
pristine plan. Two of those four bugs were invisible locally because the
uploaded plan carries none of the scars the committed one does.
