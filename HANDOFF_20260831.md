## 1. THE SHADERS WERE ALWAYS THERE

SHIPPING.md said the Reduced CSDK ships no shaders, so a DepotDownloader pull
of two depots was required. That was read off community docs and never
checked. **It is false.** The CSDK has plenty of `.vcs` files, packed in VPKs
that had not been extracted — and the compiler resolves loose files on a
search path, not archive members.

The 2026-08-28 compile log agrees in hindsight: ninety
`Failed loading resource` lines for `materials/dev/*` and `materials/tools/*`
alongside the missing shader. That is **one** fault, not two. Everything is
still packed.

So the desktop plan is now: finish the VPK export (READ ME FIRST steps B, C
and D), delete the VPKs — deliberately, since with both present the engine
can resolve to either — and re-extract the CSDK's own `game/citadel` over the
top. The depot pull is the fallback, not the prerequisite. SHIPPING.md is
corrected with the old text kept below the correction.

## 2. dl_example is a TEMPLATE MAP. This closes the lid.

The prefab probe ended somewhere nobody predicted. Two `CMapInstance`
elements, **zero external prefab paths** — so the instances are embedded and
there was never a second file. Then the census: **58 targetnames in the whole
file, and not one contains grate, ladder or lid.**

The twelve `OnDestroyed -> Kill` connections point at entities that do not

    nuetral_shop_sideofmapname_disable_relay

`lanecolor`, `sideofmapname`, `teamname`, `locationname`. **Fill-in-the-blank
slots.** dl_example is a template, pre-wired to names the mapper is expected
to create.

So `rebels_yellow_grate_brush` was never a shipped entity. There is no
classname to copy because the example declines to provide one.

**`func_brush` is therefore the ANSWER, not a placeholder.** `base.fgd` puts
`Kill` on the `GameEntity` base so any entity answers it; `func_brush` is the
standard solid with a targetname. batch18's comment saying the class is "a
CHOICE, not a copy" was right for a reason we did not have at the time.

This also retires three separate open items: the lid class, the prefab hunt,
and the worry that any of it needed the depot pull.

## 3. The FGD check, and what it caught

`tools/fgd_check.py` + `.github/workflows/fgd-check.yml`. Validates every
entity against the fifteen FGDs in `docs/reference/citadel/` — **557
classes**, the complete `@include` closure. Runs in seconds, no CSDK.

First real run: 4 errors, 127 warnings, 20 notes. Triage:

- **REAL**: `teamnumber=0` on the four teleport destinations. citadel.fgd's
  `TeamNumber` base enumerates only 2, 3 and 4 (Neutral) and defaults to 4.
  There is no 0. The "0 is None" reading came from the PROXY's
  `sub_objective_lane` fields, which do list 0, and was carried to a
  different base class. Now 4.
- **REAL**: 30 `logic_relay` entities carried a `teamnumber` the class does
  not have. Gated by `TEAM_KEY_CLASSES`.
- **CHECKER'S FAULT**: `skyname` reported undeclared. `base.fgd` declares
  `skyname(resource:material)` and the key regex rejected colons in a type.
  **A false positive is the worst thing a validator does** — it sends someone
  to fix working code.
- **NOISE**: 94 camp-timing warnings, now in a documented allowlist.

Now 0 errors, 2 warnings — the two `citadel_minimap_boundary` entities, which
came from the fixture and are absent from the FGD. Trust rule: presences
strong, absences weak, fixture outranks FGD. Left alone.

**A stale-plan note was added** after this cost real time: a fix to a batch
script does not change `docs/plans/dust2_full.json`, which is a committed
artifact. The check now says when the plan is older than the scripts.

## 4. Guardians, and the vdata trap

The lane guardian is `info_super_trooper_spawn` — a spawn marker carrying a
`BossName`, tool-named "Lane Guardian" — not `npc_boss_tier1`. All nine
guardian-closes-the-shop wires in the fixture are owned by it firing
`OnTrooperKilled`. The census has 17 of them and zero `npc_boss_tier1`.

`GUARDIAN_OUTPUT` is `OnTrooperKilled`. The two had to change together.

**The trap, because it will recur**: `npc_units.vdata` really does carry
`npc_boss_tier1` with the brazier guardian model at 5500 health. That file
lists UNITS, not map entity classes. The unit is what gets spawned; the
marker is what you place.

## The pattern worth carrying forward

Four faults this session shared one shape: a conclusion drawn from a
plausible premise nobody verified. `target` for `exitpoint`.
`npc_boss_tier1`. `light_environment`. The shaders. Each was reasonable when
made and wrong, and each was cheap to check the moment anyone tried.

The FGD check exists to make that class of error fail loudly in CI. It caught
two on its first run, and it produced one of its own.
