## 1. What this project actually is

A **personal** toolkit for one developer (mobile-only for months), designed so
that an AI agent can do the work. Three stated properties, in priority order:

1. **Low friction** — reduce the manual steps in modding Deadlock
2. **Agent-friendly** — an agent is the primary operator, not a helper
3. **Optimised and modular**

It is **not** a community product, not a mod manager, not a distribution
platform, and not a newcomer onboarding experience. All four were explored this
session and explicitly rejected.

### Goal hierarchy

| Horizon | Target |
|---|---|
| First | `dl-patch` — edit hero vdata, produce an addon VPK |
| Near | Maps track: greybox map, compile, load |
| Long | Custom heroes — recombined abilities, borrowed/AI art |
| Someday | Novel mechanics (needs binary work), private server, custom modes |

Custom heroes with new models, animations AND novel mechanics is the north
star. It has three independent blockers and is **not** near-term.

## 2. Decisions — settled, do not relitigate

| # | Decision | Reasoning |
|---|---|---|
| D1 | **All C#**, four assemblies | VRF/ValvePak are .NET; in-process beats a serialisation boundary. The C#/Python hybrid's modularity came from the CLI contract, not the language split — it paid a cost for nothing. |
| D2 | **No version pinning** | Freezing served the game-mode goal, which was dropped. Record the build id on every artifact instead. |
| D3 | **CI is the permanent execution surface** | Not a mobile workaround. It is the only place the agent can verify its own work without the human acting as courier. Survives getting a desktop. |
| D4 | **Layering is build-enforced** | One assembly per layer, references encode direction, CI fails on violation. A single solution removes the process boundary that would otherwise enforce it. |
| D5 | **CLI-first, JSON envelope** | stdout is a machine interface; diagnostics to stderr. Deterministic ordering is a contract, verified in CI. |
| D6 | **Fixtures from SteamDB GameTracking-Deadlock** | Public repo of game files. No install, no Steam credentials, CI can clone it. This is what unblocked mobile development. |
| D7 | **Structural validity is the honest ceiling** | Nothing can be confirmed to LOAD until hardware exists. Tools must say "structurally valid", never "works". |
| D8 | **One tool at a time**, built and CI-verified before the next is designed | Multi-phase speculative specs were rewritten three times this session. Token budget is the binding constraint. |

## 3. Discarded — do NOT re-propose

| Discarded | Why |
|---|---|
| **General VPK extraction (`dl-extract` as a product)** | Source2Viewer-CLI already does it (`--vpk_list`, `--vpk_dir`, `-e`, `-d`). Demoted to internal, frozen. |
| **KV3 → JSON tooling** | Solved several times: Zehmosu/kv3parser, STmihan/deadlock-data-extractor, deadlock-wiki/deadbot. |
| **Reconstructed FGD** | The game ships `citadel.fgd` (declared in `gameinfo.gi`). Valve's is better than ours would be. |
| **`dl-diff` as first build** | Justified by patch-breakage pain — an existing-modder problem. Not this project's user. Still on the list, but not first. |
| **Version pinning / frozen build** | See D2. |
| **Single-exe distribution, installers, onboarding** | Community-product features. Not a community product. |
| **Self-healing crash diagnosis, time estimates in errors** | Same. Also: a tool confidently offering a wrong fix is worse than one admitting ignorance. |
| **Hosted server for users** | No users. |
| **Mod manager / server manager space** | Crowded, well served, not our problem. |
| **Renting cloud Windows machines** | Ruled out by the developer. |
| **Pausing the project until hardware exists** | Rejected — D6 made mobile work viable. |

## 4. What exists and works

Repo: `github.com/tnauq/Dl_toolkit` (public).

```
src/Deadlock.Contracts    JSON envelope, exit codes. Bottom of the graph.
src/Deadlock.Format       VpkIndex (read), VpkWriter (synthetic fixtures)
src/Deadlock.Tools        dl-extract (frozen, internal)
src/Deadlock.MakeFixture  dl-mkfixture
compare.py                round-trip verification
.github/workflows/format-smoke.yml
.github/workflows/inbox.yml
docs/
```

**`format-smoke` is green** and proves, with zero game files:

- builds on net8.0 / ubuntu-latest; ValvePak resolves
- layer boundaries hold
- exit code 3 = missing dependency, distinct from misuse (2)
- `dl-extract` output byte-identical across runs
- **the VPK round trip**: written CRC32 (computed via `System.IO.Hashing`,
  independent of ValvePak) matches ValvePak's reported CRC32 on read-back

### Verified facts worth not re-deriving

- `PackageEntry.CRC32` **is** the CRC32 of file contents → index-only diffing
  is sound
- `ArchiveIndex` = 32767 (0x7FFF) for entries stored in the dir file
- ValvePak 4.0.0.142 requires `System.IO.Hashing >= 9.0.11`; lower fails NU1605
- ValvePak can **write** archives (`AddFile` + `Write`) → fixture-free testing
- `FindEntry` is a linear scan without `OptimizeEntriesForBinarySearch()`
- Generated `.slnx` must not be committed — stale ones poison `dotnet new sln`

## 5. Mod format — how a Deadlock mod actually works

- A mod is a VPK at `Deadlock/game/citadel/addons/pak##_dir.vpk`, `##` from
  01–99. **Lower number = higher priority.**
- Requires a one-time `gameinfo.gi` SearchPaths edit.
- **vdata mods are established practice** — a custom-heroes vdata mod exists.
- **Cosmetic changes mostly work online; vdata changes may not.** This is why
  private servers / custom games are the eventual target.

## 6. Compiling — LARGELY ANSWERED 2026-08-09

**`resourcecompiler.exe` runs headless on `windows-latest`.** Verified by the
`probe compiler` workflow: launched from a bare extracted CSDK, printed full
usage, exited cleanly. No tools install, no game install, no missing DLLs.
The mobile compile path is viable.

The CSDK lives as split release assets on tag `csdk-12` (see FINDINGS,
"Distribution of the CSDK in CI"). Reassembly must be done in Python — bash on
the Windows runner cost four revisions.

**The one remaining gap:**

```
Can't find 'game\citadel\gameinfo.gi'
```

The compiler needs a game directory to build for. `-game <path>` names the
`gameinfo.gi`. That file is small text, available from the Valve Developer
Community wiki and GameTracking-Deadlock, so it is synthesizable in CI.

**Still open:** whether the game loads UNCOMPILED text vdata from an addon.
A real GameBanana mod was inspected and contains `.vdata_c` — but that shows
what modders do, not what the game accepts. Needs a running game; deferred to
hardware.

## 8. Working constraints

- **Mobile-only for months.** Windows machine eventually, owned not borrowed.
- **Always deliver FULL file contents, never partial snippets.** Partial pastes
  truncate on mobile — this caused four separate CI failures this session.
- **Multi-file delivery goes via zip** → repo root → run the `inbox` workflow.
  File cards download flat and lose directory structure.
- `inbox.yml` uses a PAT (`secrets.PAT`) with Contents + Workflows write, so
  workflow files can be updated without the web UI. PAT pushes DO trigger other
  workflows.
- **Token cost is the binding constraint**, not the developer's hours. The
  agent does 100% of the coding.
