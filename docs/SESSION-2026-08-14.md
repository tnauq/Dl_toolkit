## 1. The chain is closed

```
mapplan.json -> dl emit -> KV2 text -> dmxconvert -> binary vmap 40
```

All of it phone-drivable. Green workflows: `probe-dmxconvert`,
`probe-dmx-noids`, `map-smoke`, `emit-smoke`, `plan-roundtrip`.

Three corrections, each of which SHRANK the project:

1. **`.vmap` is DMX binary 9, not KV3.** VRF and `Kv3Document` do not
   apply to map source.
2. **`dmxconvert.exe` is in `csdk/bin_cs2/win64`** beside
   resourcecompiler, and converts keyvalues2 text to binary at
   `format vmap 40`. **We never write binary DMX.**
3. **The one-box fixture was already in the file.** The smallest
   `CDmePolygonMesh` in `dl_example.vmap` is a single quad with every
   data stream visible.

## 2. THE COMPILER ANSWER — `[V-CI]`, and it is a dead end

The question from 2026-08-13, *does `resourcecompiler` build a `.vmap`
headlessly*, is **answered: not on a GPU-less runner.**

Evidence, from `probe-compiler-control` and `probe-compiler-flags`:

| run | input | result |
|---|---|---|
| C1 | real vdata, citadel mount | **exit 0, compiled in under a second** |
| C2 | our vmap, citadel mount | hung, killed at 150s |
| C3 | our vmap, addon mount | hung, killed at 150s |
| D1 | `-crc` our vmap | **CRC `0x520FB132` in seconds** |
| D2 | `-crc` the fixture | **CRC `0xA01748CD` in seconds** |
| D3/D4/D5 | `-novpk`, `-fshallow`, `-skiptype` | all hung, 133 lines each |

**The cause is line 4 of every hung run:**

```
Creating device for graphics adapter 0 'Microsoft Basic Render Driver'
```

The map path spins up the render system. The vdata path never does.
GitHub-hosted Windows runners have no GPU, only Microsoft's software
rasterizer, and the compile freezes shortly after device creation while
failing to load every `.vmat_c` and `.vtex_c` the renderer wants.

**What this does NOT mean.** It is not a problem with the emitted file.
D1 proves the compiler READS our vmap fine and reports its CRC. Parsing
was never implicated. It is a property of the environment.

**Two leads died here and must not be revisited:**

- **FGDs are not the cause.** C1 emitted the identical
  `Unable to find fgd file models_gamedata.fgd` warnings and finished
  anyway. GameTracking also ships **no `.fgd` files at all**.
- **`-novpk` / `-fshallow` / `-skiptype` change nothing.** All three hung
  at exactly 133 lines, because the stall happens before any of those
  flags become relevant.

**Also proven, upgraded from `[I]` to `[V-CI]`:** `-game` does NOT decide
CONTENT — **gameinfo.gi does**. C3 ran with
`ModGameSubdir: citadel_addons/dl_toolkit_test` and resolved CONTENT to
`build\content\citadel\` until the gameinfo itself was patched to declare
its own mount, after which
`CONTENT build\content\citadel_addons\dl_toolkit_test\` appeared first.
An addon needs a gameinfo declaring its own `Game` line.

**Decision: STOP HERE.** Lesson 2, cap the yak-shave. It is off the
critical path — "done" was settled as layouts portable to Hammer, and the
compiler was deliberately demoted to a warning. Going further means a paid
GPU runner or undocumented flags, for something already agreed to be
unnecessary.

**The irony, for the record:** the GPU limitation genuinely was not about
rendering on the phone. It bites on the build machine instead.

## 3. Settled decisions — do not relitigate

| | |
|---|---|
| "Done" for maps | layout maps at a scale portable to Hammer. NOT compiler acceptance, NOT in-game load |
| Source of truth | `.mapplan.json` box list. The `.vmap` is a regenerated artifact. When Hammer opens it, Hammer becomes the source and the JSON goes stale BY DESIGN |
| Encoding | emit `keyvalues2_noids`; dmxconvert makes the binary |
| No GUIDs | noids writes ids only for elements referenced MORE THAN ONCE (767 ids / 768 shared). Nothing in the emitter's scope is shared. Adding groups, selection sets, paths or connections breaks this |
| Grid | guides, does not constrain. Origins snap to 64, extents free |
| Binary DMX reader | DESIGNED AND DEFERRED. No consumer: nothing outside CI reads a `.vmap`, and CI is Windows anyway |
| Viewer | textured HTML walkthrough, orange dev textures drawn procedurally. The ASCII city stays a separate off-critical-path project |
| Scale | 1 unit = 1 inch = 0.0254 m; 1 m = 39.37 u. See `SCALE.md` |
| Compiler map probe | a warning, and now a CLOSED one |

## 6. Open, and honestly open

- **Does Hammer read a text-encoded `.vmap`?** Unknown. One Discord
  question. Blocks nothing: export goes through dmxconvert either way.
- **The document floor.** The fixture is maximal so it cannot say what is
  required. The emitter currently ships root, world, visibility,
  variables, selection set and cameras, and dmxconvert accepts it. What
  HAMMER tolerates is unknown until hardware.
- **`smoothingAngle` 180 vs 40.** Both appear in the fixture. 180 was
  taken from the fully-dumped element. Low confidence, one line.
- **Texture axes and UVs are a first cut.** No box existed in the fixture
  to compare against — its smallest mesh is a quad.
- **Rotated boxes** are emitted but untested beyond the identity case.
- **Cell size 64** is `[?]`. Deriving metres per unit does not derive the
  right cell size.
- **`DmxReadResult`** is a local result type; merge with Contracts' Result
  shape if one exists.
- **Fold `dl map info` into the one `dl` binary** and delete MapSmoke.

## 7. Process lessons added today

6. **An assert should measure the thing, not the guess about the thing.**
   `probe-dmx-noids` asserted zero ids and hard-failed. Reality: noids
   strips ids from singly-referenced elements and keeps shared ones. The
   run held a precise answer; the assert turned it into a red X.
7. **Prototype the grammar in a scripting language before writing code you
   cannot compile.** The KV2 reader, the half-edge builder and MapReader
   were each validated in Python against real bytes first. All three
   compiled and passed CI on the first attempt, from an environment with
   no dotnet.
8. **Run the hypothesis before the control.** `probe-compiler-map` put the
   control first, hung on it, and learned nothing about the layout that
   mattered.
9. **Cap every external tool call in CI.** A hung Source tool eats the
   runner's full six hours. Watchdog, closed stdin, step timeout.
10. **A correct change can break something it never touched.** Moving the
    viewer's touch listeners from the canvas to the document was necessary
    for the d-pad and silently killed every footer control, because
    `preventDefault` then applied to taps on them.

**Corollary still holds: a green run is not a correct run.** Every stage
boundary carries an identity check, and dmxconvert sits in the middle of
the read/write loop so a shared misunderstanding between our reader and
writer cannot cancel out.

## 8. Ceiling

Everything is **structurally valid, accepted by dmxconvert, and
semantically unchanged across a round trip**. That is one rung above D7.
It is not "Hammer opens it" and not "Deadlock loads it". Tools say
"structurally valid", never "works".
