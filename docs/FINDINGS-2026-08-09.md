## KV3 reading and writing — `[V-CI]`, probe-kv3 runs 2026-08-09

**VRF round-trips source vdata without semantic loss.** A 2.1 MB
`CitadelHeroData_t` file (`game/citadel/pak01_dir/scripts/heroes.vdata`) parsed
and re-serialised with no edit produced:

| | original | round-tripped |
|---|---|---|
| keys (` = ` lines) | 63,490 | 63,490 |
| `resource_name:` prefixes | 453 | 453 |
| `_class` markers | 60 | 60 |
| quote characters | 47,282 | 47,282 |
| bytes | 2,107,060 | 2,199,027 |

**We do NOT need to write our own KV3 serializer.** This was the open question
that gated `dl-patch`, and it is closed.

**The output is REFORMATTED, cosmetically, in three ways:**

- floats padded to six decimal places — `7.2` becomes `7.200000`
- inline arrays exploded one element per line — `m_colorUI = [ 94, 176, 131 ]`
- blank lines inserted after the header and between array elements

That accounts for the 92 KB and ~6,000 extra lines.

**No precision is at risk in this file.** It contains zero floats with more
than six decimal places, zero scientific notation, and zero values large enough
for six-dp padding to round. `[V-CI]` for hero vdata; **unverified for item and
ability vdata**, which may differ.

**Hero vdata contains no comments** (0 lines matching `^\s*//`), so the usual
"a parser discards comments" objection does not apply here.

**Consequence for CI assertions.** A byte-identical assertion against the
ORIGINAL is impossible. Against a no-op round trip it is trivial, and that is
what `patch-smoke` does — baseline first, then diff the patched file against
the baseline. Same guarantee, reformatting held constant on both sides.

## VRF targets net9.0 only — `[V-CI]`, probe-kv3 2026-08-09

`ValveResourceFormat 12.0.4261` fails restore on net8.0 with **NU1202**; it
supports net9.0 exclusively. The rest of the solution is net8.0.

- `Deadlock.Patch` and `Deadlock.Probe.Kv3` are net9.0. Everything else stays
  net8.0. A net9.0 project may reference a net8.0 one; **not the reverse.**
- **If a second shipping tool needs VRF, migrate the whole solution** rather
  than accumulating per-project exceptions.
- This is why `Deadlock.Patch` does not yet reference `Deadlock.Contracts` —
  see the corrections entry below.

## VRF KV3 object model — `[V-CI]`, probe-kv3 surface dump 2026-08-09

Dumped by reflection from the loaded assembly, not from documentation:

```
KV3File.Root          -> KVObject          { get; set; }
KVObject.Properties   -> Dictionary<string, KVValue>   { get; }   PROPERTY readonly,
                         DICTIONARY MUTABLE — in-place assignment works
KVObject.IsArray      -> bool     arrays are KVObjects too
KVObject.AddProperty(string, KVValue)
KVValue.Type          -> ValveKeyValue.KVValueType   { get; }   DIFFERENT ASSEMBLY
KVValue.Flag          -> KVFlag   { get; }
KVValue.Value         -> object   { get; }   a nested block boxes a KVObject
KVValue ctor          -> (KVValueType, KVFlag, object)
KVFlag                -> None, Resource, ResourceName, Panorama, SoundEvent, SubClass
```

**The mutation technique that follows from this:** to change a scalar, reuse
the existing `Type` and `Flag` and swap only the boxed value. Our code then
names no `KVValueType` member, avoids the cross-assembly reference entirely,
and preserves typed prefixes such as `resource_name:` for free. Classify on the
RUNTIME type of `.Value` (`bool`, `string`, `double`, integer), which the live
dump confirms directly.

## `dl-patch` v1 — `[V-CI]`, patch-smoke 2026-08-09

Green against a real hero vdata, GameTracking commit
`0f32ac2411aa8e6832eb233b1db2d68800974714`.

Proven:

- **One line changes and nothing else.** Diff against the no-op baseline is
  exactly `38c38`, `EMaxHealth = 780.000000` → `1234.000000`, in a 116,786-line
  file.
- The patched file **re-parses**.
- Output is **byte-identical across repeated runs**.
- Exit codes: 5 path not found, 6 type mismatch, 4 input unreadable, 2 misuse.
- **Flagged values are refused by name** — `m_strModelName is a ResourceName
  value; v1 sets plain scalars only`.
- `--dry-run` writes no file.
- All-or-nothing: any failed edit means nothing is written.

**Verified paths in hero vdata**, useful and version-sensitive:

- file: `game/citadel/pak01_dir/scripts/heroes.vdata` — note GameTracking
  mirrors the VPK's INTERNAL layout, so the `pak01_dir` segment is part of the
  path. An addon's path will differ.
- `hero_base.m_mapStartingStats.EMaxHealth` = `780.0` at that commit
- hero blocks are named `hero_inferno`, `hero_gigawatt`, `hero_atlas`,
  `hero_wraith`, `hero_hornet`, `hero_ghost` … — **internal codenames, not
  display names**

**NOT proven, and the tool must keep saying so (D7):** that the game loads the
result. One file of one type (`CitadelHeroData_t`) was exercised; item and
ability vdata are untested.

## Corrections

**2. `EditReport.From` — the envelope's `from` is not literally the file text.**
`dl-patch` renders numbers with `"R"` formatting, so a field reading `780.0` in
the file reports as `780` in the JSON envelope. Cosmetic today. It becomes real
when batch adds an `expect` guard: **that comparison must be numeric, not
string**, or every float guard fails spuriously.

**3. Three compile failures came from writing against an unread API.**
`Kv3Document.cs` was drafted against guessed VRF signatures and failed on
CS0102, then CS0266, then CS0103 x8. The first surface dump did not catch it
because its type filter matched only names containing `KV3`, which excluded
`KVObject`, `KVValue` and `KVType` — the three that mattered.

This is the same failure already recorded as correction 1 ("spans, not
copies"), repeated. **Generalised rule: a probe against a library must dump the
surface it is about to be used through, not the surface that shares its name.**

**4. `Deadlock.Patch` does not reference `Deadlock.Contracts` yet.**
`Envelope.cs` mirrors the envelope shape locally. This is deliberate — the
Contracts type names had not been read, and guessing them is the mistake above.
Folding it back is a rename, complicated only by the framework split: Contracts
is net8.0 and Patch is net9.0.
